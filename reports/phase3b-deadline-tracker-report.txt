SCOPE
═══════════════════════════════════════════════════════════════════════════════

Phase 3B builds the client-side deadline calculator and wires it to the live
rules API. The backend deadline computation is unchanged and remains
authoritative. The client now previews the deadline live as the user types,
and submits its computed value for backend validation on each assessment.

═══════════════════════════════════════════════════════════════════════════════
WASM DECISION
═══════════════════════════════════════════════════════════════════════════════

A clean JS fallback was implemented rather than WASM for Phase 3B. Reasons:
  - WASM requires a separate compile toolchain (Rust/Emscripten) and a
    build step that would extend this phase significantly.
  - The arithmetic (month addition, integer subtraction) is trivial and
    identical in JS and Python.
  - The JS module (deadline.js) mirrors deadline.py function-by-function,
    so correctness is validated by the Python test suite.
  - WASM can replace the JS module in Phase 3C or later without any API
    changes — the interface is stable.

DEADLINE ARITHMETIC (client/public/js/deadline.js)
═══════════════════════════════════════════════════════════════════════════════

Mirrors backend/engine/deadline.py exactly. No legal values hardcoded.

addCalendarMonths(d, n):
  Adds N calendar months, clamping to month-end. Mirrors _add_months().

computeDeadline(edtStr, timeLimitMonths, ecDayAStr, ecDayBStr):
  Step 1 — base limit:
    anniversary = addCalendarMonths(edt, timeLimitMonths)
    baseLimit   = anniversary - 1 day   (ERA 1996 s.111(2))

  If no EC dates:
    return { limitation_date: baseLimit, ... }

  Step 2 — EC stop-clock (ERA 1996 s.207B):
    if dayB < dayA: return { error: '...' }
    pauseDays = daysDiff(dayA, dayB)       [Day A+1 through Day B inclusive]
    adjusted  = baseLimit + pauseDays

  Step 3 — floor:
    floor      = addCalendarMonths(dayB, 1)
    final      = max(adjusted, floor)
    floorApplied = (final === floor && floor > adjusted)

fetchDeadlineRules(apiBase, claimType):
  Fetches /rules/{claimType}, extracts time_limit_months rule.
  Returns { timeLimitMonths, authorityRef, authorityUrl, effectiveFrom,
            effectiveTo, lastVerifiedAt }.
  This is the ONLY source of timeLimitMonths — never hardcoded.

BACKEND VALIDATION
═══════════════════════════════════════════════════════════════════════════════

The backend is always authoritative. When POST /assess includes client_deadline:

  - Backend computes its own deadline from facts (unchanged pipeline)
  - Compares backend deadline_info.limitation_date against client_deadline
  - If they differ: deadline_mismatch=True, deadline_mismatch_detail logged
  - If they match: deadline_mismatch=False
  - If client_deadline not supplied: deadline_mismatch absent from response

The mismatch detail includes both client and backend values, enabling
monitoring for JS/Python divergence. Mismatch is logged as WARNING server-side.
