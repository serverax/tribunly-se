═══════════════════════════════════════════════════════════════════════════════
PAYMENT GATING (MOCK MODE)
═══════════════════════════════════════════════════════════════════════════════

PAYMENT_ENABLED=false (default in Phase 3D):
  - Any non-empty payment_token = paid (mock)
  - No Stripe integration  -  Phase 4

Document gate behaviour:
  - No token → preview (first 28 lines) + payment_required=True + gate notice
  - Token present → full document + payment_required=False

Preview notice (verbatim in every preview):
  "PREVIEW ENDS HERE / Full document access requires payment. /
   There are no hidden charges  -  the full price is shown before any payment
   is taken. lawapp never charges without your consent."

UI: "Activate full access (demo)" button sets payment_token in sessionStorage.
The copy-to-clipboard button is suppressed when payment_required=True.

GUARDRAIL: No hidden payment. Price must be shown before any charge. (Phase 4)

CASE SAVING
═══════════════════════════════════════════════════════════════════════════════

Uses existing `cases` table from migration 001. Fields stored:
  - claim_type, jurisdiction
  - assessment (jsonb)  -  structured pipeline output; no PII (de-id'd by pipeline)
  - key_dates (jsonb)  -  {edt, deadline_date}
  - status = 'diagnosis'
  - user_id = NULL  -  authentication is Phase 4
  - facts_encrypted = NULL  -  encryption at rest is Phase 5

GUARDRAIL: Raw user facts never stored. Only structured assessment output stored.
NOTE: Phase 3D is local/test-only. facts_encrypted = NULL is not production-ready.

Endpoints:
  POST /cases  → 201 {case_id, created_at}
  GET  /cases/{case_id} → case record

═══════════════════════════════════════════════════════════════════════════════
HANDOFF LEAD CAPTURE
═══════════════════════════════════════════════════════════════════════════════

New table: handoff_leads (migration 007)
  - id, case_id (optional FK), trigger_reason, name, email, phone (opt),
    case_summary (opt), consent_given (must be true), created_at
  - DB constraint: consent_given = true enforced at DB level

Trigger conditions (any of):
  - recommended_next_step = "seek_solicitor"
  - insufficient_grounding = true
  - strength = "low"

Endpoint: POST /handoff/leads → 201 {lead_id, status, created_at, message}

Validation:
  - consent_given=false → 422
  - invalid trigger_reason → 422
  - missing name or email → 422

Response message includes:
  "lawapp is not a solicitor and does not provide regulated legal advice."
  "This is free to you  -  no charges apply for this referral."

Phase 3D: stored locally. No live referral sent. Phase 6 integration.

GUARDRAIL: No solicitor-client relationship created. No representation implied.
GUARDRAIL: Referral is free to the user  -  stated explicitly in API response.
