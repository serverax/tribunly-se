DEADLINE URGENCY (backend/engine/reminders.py)
═══════════════════════════════════════════════════════════════════════════════

compute_urgency(limitation_date_str, today_str=None) → dict

Thresholds (deterministic, no model):
  delta < 0        → "expired"       (deadline has passed)
  0 <= delta <= 7  → "due_within_7"  (act immediately)
  8 <= delta <= 14 → "due_within_14" (act soon)
  15 <= delta <= 30 → "due_within_30" (take action)
  > 30             → "safe"

Returns: urgency, urgency_label, days_remaining, limitation_date, as_of, is_urgent

GUARDRAIL: urgency computed from stored limitation_date only.
The LLM never computes, recalls, or estimates deadline information.

NEW ENDPOINTS (backend/api/main.py)
═══════════════════════════════════════════════════════════════════════════════

GET  /cases/{case_id}/deadline[?as_of=YYYY-MM-DD]
  Returns deadline info + urgency state from stored key_dates.
  as_of: optional reference date override for testing.

POST /cases/{case_id}/reminders
  Creates a reminder_events record (in_app channel, pending status).
  Validates reminder_type against allowed set.
  Phase 3E: local only; no email/SMS.

GET  /cases/{case_id}/reminders
  Lists reminder events for a case, ordered by created_at DESC.

SAVED-CASE RETURN FLOW (client/public/pages/saved_case.html)
═══════════════════════════════════════════════════════════════════════════════

Navigation: /pages/saved_case.html?case_id=UUID

Page behaviour:
  - Extracts case_id from URL params
  - Fetches /cases/{case_id} and /cases/{case_id}/deadline in parallel
  - Renders: viability, deadline with urgency badge, weaknesses, resume links
  - Shows handoff section if seek_solicitor / insufficient_grounding / low
  - If case not found: clear error, no fabrication
  - Full legal notice present at top and bottom
