STORAGE — LOCAL/TEST-ONLY (NOT PRODUCTION-READY)
═══════════════════════════════════════════════════════════════════════════════

Phase 4A uploads are stored at: /tmp/lawapp_uploads/{case_id}/{upload_id}
  - No encryption at rest (Phase 5)
  - Container ephemeral storage only
  - Every response includes storage_note: "LOCAL STORAGE — Phase 4A only..."
  - DB stores only metadata (no file content in DB)

Phase 5 replacement: encrypted object storage (S3/GCS + AES-256-GCM).

═══════════════════════════════════════════════════════════════════════════════
MOCK EXTRACTION (backend/engine/extraction.py)
═══════════════════════════════════════════════════════════════════════════════

Phase 4A uses mock extraction — no actual OCR or LLM.
Real file bytes are NEVER read by the extraction module.

Confidence scores per doc_type (higher = more reliable):
  dismissal_letter:    employer_name(0.85) edt_candidate(0.88) notice_period(0.62)*
  employment_contract: employer_name(0.92) employment_start_date(0.87) gross_pay(0.78)
  email_chain:         all fields 0.42–0.58* (flagged)
  payslip:             employer_name(0.93) gross_pay(0.95)
  other:               all fields 0.38–0.40*

*Fields < 0.70 are flagged with flagged=True in response.

LOW_CONFIDENCE_THRESHOLD = 0.70

Phase 5+: replace mock with Tesseract/Textract/Azure Form Recognizer.
The interface is stable — callers use the same field dict shape.

═══════════════════════════════════════════════════════════════════════════════
USER CONFIRMATION FLOW
═══════════════════════════════════════════════════════════════════════════════

All extracted facts start as "extracted_unconfirmed".
User must explicitly update status via PATCH /facts before facts affect case data.

States:
  extracted_unconfirmed → user has not reviewed
  user_confirmed        → accept extracted value as-is
  user_corrected        → override with user-supplied value
  rejected              → discard; never applied

Non-PII fields that can be applied to case.key_dates (after confirmation):
  edt_candidate, employment_start_date, gross_pay,
  dismissal_reason, notice_period, key_procedure_concerns

PII fields EXCLUDED from apply-confirmed (Phase 5):
  employer_name, employee_name
  (Requires encryption at rest before persistent storage)

═══════════════════════════════════════════════════════════════════════════════
ENDPOINTS
═══════════════════════════════════════════════════════════════════════════════

POST /cases/{case_id}/uploads        — upload document (multipart)
GET  /cases/{case_id}/uploads        — list upload metadata (no file content)
POST /cases/{case_id}/uploads/{id}/extract          — mock extraction
PATCH /cases/{case_id}/uploads/{id}/facts           — confirm/correct/reject
POST /cases/{case_id}/uploads/{id}/apply-confirmed  — apply to case key_dates

Supported content types: application/pdf, image/jpeg, image/png, image/tiff
Supported doc_types: dismissal_letter, employment_contract, email_chain,
                     payslip, other

DATA PROTECTION NOTES
═══════════════════════════════════════════════════════════════════════════════

  - Raw file bytes: NEVER logged (metadata only in logger calls)
  - Raw file bytes: NEVER sent to external service (no external calls)
  - Raw file bytes: NEVER returned in API response
  - File content: NOT stored in DB (storage_ref points to local path)
  - PII in extracted facts: NOT applied to persistent storage (Phase 5)
  - All extraction responses include: "check every field carefully"
  - Apply-confirmed includes: "PII fields not applied until Phase 5"
