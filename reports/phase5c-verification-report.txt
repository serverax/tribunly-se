DATA-PROTECTION REPORT  -  PRIORITY CATEGORISATION
═══════════════════════════════════════════════════════════════════════════════

Phase 5C categorises DP gaps into:

LAUNCH BLOCKERS (must fix before any real user data is processed):
  - DPIA not completed (legal requirement before processing)
  - No documented legal basis for data processing (GDPR Art.6/Art.9)
  - No privacy notice / transparency information for users

PRODUCTION BLOCKERS (must fix before production; closed beta possible):
  - No encryption at rest for uploaded documents
  - No encryption for cases.facts_encrypted column
  - No encryption for handoff_leads PII (name, email)
  - No data retention / deletion policy (Art.17 UK GDPR)
  - User authentication not implemented

POST-LAUNCH ENHANCEMENTS:
  - Structured logging with PII audit trail
  - Automated log scanning
  - Full access control for admin endpoints
  - Live solicitor referral network

IMPLEMENTED:
  - Model boundary de-identification (14 PII types stripped)
  - boundary_log in every assess() response
  - Upload bytes never logged or sent externally
  - Handoff consent required at DB constraint level
  - Extracted PII facts excluded from apply-confirmed
