1. DEPLOYMENT READINESS FOUNDATION
═══════════════════════════════════════════════════════════════════════════════

Module: backend/engine/config_validation.py
FastAPI lifespan: validate_startup_config() called at startup.

DEPLOYMENT_MODE=development (default): warns about missing vars, does not fail.
DEPLOYMENT_MODE=production:
  - Required vars: POSTGRES_PASSWORD, ADMIN_API_KEY, ENCRYPTION_KEY
  - Missing any → StartupConfigError → startup aborted (sys.exit equivalent)
  - PAYMENT_MODE=stripe_live requires STRIPE_SECRET_KEY

GUARDRAIL: Only var names logged, never values.

═══════════════════════════════════════════════════════════════════════════════
2. END-USER AUTHENTICATION FOUNDATION
═══════════════════════════════════════════════════════════════════════════════

Module: backend/engine/user_auth.py
LAWAPP_AUTH_MODE env var:
  none (default): no auth — all case endpoints open (backward compat)
  mock:           X-User-ID header (any valid UUID); case ownership enforced
  jwt:            not yet implemented (Phase 7 — returns 501)

When mock auth is active:
  POST /cases: associates case with user_id (upserts into users table)
  GET /cases/{id}: requires X-User-ID matching case.user_id
  Admin key (X-Admin-Key) always overrides ownership check
  Cases with no user_id (legacy): accessible to any authenticated user

GUARDRAIL: User ID values never logged.
GUARDRAIL: Admin API key is completely separate from end-user auth.
