2. KMS/HSM BEHAVIOUR IMPLEMENTED
═══════════════════════════════════════════════════════════════════════════════

  Provider hierarchy:

    EnvKeyProvider (KEY_MANAGEMENT_MODE=env):
      - Reads ENCRYPTION_KEY from env var
      - is_production_grade()=False (env var not HSM-backed)
      - Suitable for dev, test, controlled beta

    KmsStubProvider (KEY_MANAGEMENT_MODE=kms_stub):
      - Validates KMS_KEY_ID is configured
      - kms_connected=False always (Phase 7B stub — no real KMS API call)
      - is_production_grade()=True when KMS_KEY_ID configured
        (signals correct intent; real API in Phase 7C)
      - Falls back to EnvKeyProvider for actual key material
      - Required: KMS_KEY_ID; Optional: KMS_ENDPOINT, KMS_REGION

    DisabledProvider (KEY_MANAGEMENT_MODE=disabled):
      - No encryption
      - is_production_grade()=False
      - Production blocker

  Config validation (production mode):
    kms_stub without KMS_KEY_ID → missing_required includes "KMS_KEY_ID"
    disabled → missing_required includes "encryption required"

  What Phase 7C will complete:
    - Real KMS API calls (AWS KMS, GCP KMS, HashiCorp Vault)
    - kms_connected=True when genuinely connected
    - Encrypted data keys, key rotation

  GUARDRAIL status:
    - Key material values NEVER logged
    - KMS_KEY_ID value NEVER logged (could expose key topology)
    - KMS endpoint URL NEVER logged (internal infrastructure)
