3. KMS CONNECTION BEHAVIOUR
═══════════════════════════════════════════════════════════════════════════════

  AwsKmsProvider operations:

    get_encryption_key():
      - Calls boto3 KMS.GenerateDataKey(KeyId=ARN, KeySpec="AES_256")
      - Converts 32-byte plaintext to URL-safe base64 (Fernet-compatible)
      - Returns None on any error (fails closed)
      - GUARDRAIL: key material value NEVER logged

    health_check():
      - Calls boto3 KMS.DescribeKey(KeyId=ARN)
      - Returns True if accessible; False on any error
      - GUARDRAIL: ARN value NEVER logged

  Production readiness fields (AwsKmsProvider):
    provider_configured:     True when AWS_KMS_KEY_ARN set
    aws_region_configured:   True when KMS_REGION or AWS_DEFAULT_REGION set
    kms_connected:           True/False from health_check, or N/A if not checked
    envelope_encryption:     NOT_IMPLEMENTED  -  Phase 7D

  Note: Full envelope encryption (persisting CiphertextBlob alongside ciphertext
  to allow key rotation) is Phase 7D. Phase 7C demonstrates real connectivity.

  AWS credentials: NEVER in repo. Standard credential chain:
    - AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY (explicit)
    - IAM instance role / ECS task role / EC2 instance profile
    - ~/.aws/credentials (local dev)
